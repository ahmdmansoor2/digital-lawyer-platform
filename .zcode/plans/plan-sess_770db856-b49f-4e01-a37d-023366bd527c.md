# خطة تنفيذية: تحسين نظام النشر اليومي القائم + جدولته عبر ZCode

## 📌 خلاصة الاكتشاف
يوجد نظام نشر يومي كامل في `scripts/blog-publisher/` يحقق 95% من طلبك:
- `daily-publish.cjs` — يولّد مقالاً عبر Gemini، يبني HTML كامل (RTL، SEO، AdSense، disclaimer)، يحدّث `index.html`، ينشر على Firebase Hosting، يحفظ مسودة عند الفشل.
- `topics.json` — 12 موضوع Evergreen جاهز.
- `run-daily.ps1` — wrapper PowerShell (لكنه غير مربوط بأي scheduler).
- `published-log.json` — سجل لتفادي التكرار.

**لا داعي لبناء CMS Firestore جديد.** العمل المتبقي = تحسين + جدولة.

---

## 🔍 ثغرات اكتُشفت تحتاج معالجة

1. **عدم مزامنة السجلّين**: `scripts/published-log.json` (6 مقالات، آخرها اليوم `tenant-rights-egypt`) ≠ `scripts/blog-publisher/published-log.json` (5 مقالات، `last_run: null`). السكربت يقرأ الثاني فقط — قد يُكرّر `tenant-rights-egypt`.
2. **`log.skipped` غير مهيّأ**: السكربت يفترض وجود `log.skipped.push(...)` لكن الملف لا يحتوي المفتاح — قد يُخطئ.
3. **لا بحث ويب عن المستجدات**: السكربت يعتمد كليًا على `topics.json` (Evergreen). متطلبك: يبحث أولًا عن آخر 24-48 ساعة.
4. **لا جدولة فعلية**: `run-daily.ps1` كتب لكن لم يُربط بـ Windows Task Scheduler ولا بأتمتة ZCode.
5. **عند نفاد topics**: السكربت يطبع رسالة فقط ويخرج بـ 0 دون تنبيه واضح للحاجة لتعبئة جديد.

## ✅ خطة التنفيذ (مرحلة بمرحلة)

### المرحلة 1 — إصلاح ثغرات السكربت القائم (منخفض المخاطر)

**ملف: `scripts/blog-publisher/daily-publish.cjs`**

- **1.أ. تهيئة `skipped` آمنة**: في `main()`، بعد قراءة log، أضف:
  `if (!Array.isArray(log.skipped)) log.skipped = [];` — يمنع `TypeError` عند `log.skipped.push(...)`.
- **1.ب. مزامنة السجلّين**: قبل `pickTopic`، اقرأ كلا الملفين (`scripts/published-log.json` و`blog-publisher/published-log.json`)، وادمج `published` عبر `Set` من slugs، واستخدم المجموعة الموحّدة في `pickTopic`. بعد النشر، اكتب السجل في **كلا** المسارين لتفادي الانفصال مستقبلًا.
- **1.ج. تنبيه أوضح عند نفاد topics**: عند `!topic`، اطبع رسالة عربية واضحة بالاقتراح: "أعد تعبئة topics.json أو أضف مواضيع جديدة".

### المرحلة 2 — إضافة طبقة البحث عن المستجدات (متوسط المخاطر)

**ملف جديد: `scripts/blog-publisher/news-search.cjs`** (وحدة مساعدة تُستدعى من daily-publish)

- **2.أ.** WebSearch غير متاح من Node CLI مباشرة. البديل العملي: استخدام **Gemini نفسه** (`@google/genai` المثبّت) للإجابة عن: "ما آخر المستجدات القانونية في مصر خلال آخر 48 ساعة؟ أعطني 3 عناوين جذّابة فقط" مع تعليمات صارمة: لا يخترع أحداثًا محددة، يكتفي بالاتجاهات العامة.
- **2.ب.** يستخرج `title`, `slug`, `keywords`, `category` من JSON ويعيدها كـ topics مرشّحة.
- **2.ج.** `daily-publish.cjs` يجرّب `news-search.cjs` أولًا: إن أرجع مواضيع، يختار أحدها (بعد التحقق من عدم تكراره في السجل الموحّد). إن فشل أو لم يجد، يعود إلى `topics.json` (fallback يحفظ المتطلب "Evergreen").
- **2.د.** يُحفظ مصدر الموضوع في السجل: `{ source: 'news' | 'evergreen' }` لشفافية التشغيل.

### المرحلة 3 — توسيع `topics.json` (طيفي، منخفض المخاطر)
أضف ~15-20 موضوعًا Evergreen إضافيًا لتفادي نفاد القائمة بسرعة. أمثلة: "حقوق الموظف في فترة الاختبار"، "تقادم الديون"، "التظلم من قرارات الجهاز الإداري"، "الطلاق للشقاق"، "الإعسار والمصلح القضائي"، "حق المؤلف على المحتوى الرقمي"... (بالنمط الحالي في topics.json).

### المرحلة 4 — إضافة npm script + توثيق (طيفي)
**ملف: `package.json`** — أضف ضمن `scripts`:
`"blog:publish": "node scripts/blog-publisher/daily-publish.cjs"`

### المرحلة 5 — الجدولة عبر ZCode CronCreate (في جلسة منفصلة)
بعد إتمام 1-4، وفي **جلسة جديدة** (لا يمكن في الجلسة الحالية المرتبطة بجدولة سابقة):
- استدعاء `CronCreate` بالتعبير `0 9 * * 1-5` (9 صباحًا، أيام العمل بالتوقيت المحلي = القاهرة) مع prompt: تعليمات لتشغيل `npm run blog:publish` وتحليل الناتج وإبلاغ المستخدم (عنوان المقال، الرابط، حالة النشر).

### المرحلة 6 — توثيق (يلتزم AGENTS.md)
- **CHANGELOG.md**: بند يصف التحسينات.
- **README_WINDOWS_DESKTOP.md**: فقرة "النشر اليومي للمدونة" تشرح `npm run blog:publish` والجدولة.
- **(اختياري) `docs/adr/0003-blog-publishing-system.md`** — ADR قصير يوثّق القرار: تبنّي نظام HTML ثابت + Gemini بدل CMS Firestore.

## 🛡️ ضمانات الامتثال
- ✅ **AGENTS.md**: لا تكرار كود؛ ألوان `slate/emerald/indigo` (بـ HTML القائم)؛ RTL.
- ✅ **الأمان**: لا API keys في الكود (`GEMINI_API_KEY` من `.env` فقط)؛ `.gitignore` يستثني `.env`.
- ✅ **المتطلبات القانونية**: disclaimer، 800-1200 كلمة، meta description < 160، keywords، canonical، CTA.
- ✅ **عند الفشل**: لا نشر ناقص، حفظ مسودة، تسجيل السبب في `skipped[]`.

## ⚠️ المخاطر
- **خطر Gemini لـ "آخر المستجدات"** (المرحلة 2): قد يخترع أحداثًا. نُلجّم بالتعليمات "لا تخترع أحداثًا محددة، اكتفي بالاتجاهات العامة" + علامة `source: 'news'` توضح للمستخدم أنه تقديري. خطة بديلة (أكثر أمانًا، أقل قيمة): إبقاء Evergreen فقط مع WebSearch يدوي عبر agent.
- **deploy عبر `firebase deploy`**: يتطلب CLI مصادقة محليًا. سأتحقق من المصادقة القائمة قبل الجدولة. إن فشلت، يُسجّل السبب ويُحفظ المقال كمسودة (السكربت يفعل ذلك بالفعل).

## 📋 ترتيب التنفيذ (~45د)
1. المرحلة 1: إصلاح السجل + `skipped` (~10د)
2. المرحلة 3: توسيع topics.json (~10د)
3. المرحلة 4: npm script + التوثيق (~5د)
4. المرحلة 2: news-search مع Gemini + دمجها في daily-publish (~15د)
5. اختبار سريع بـ `npm run blog:publish` (dry-run) للتأكد من القراءة/الكتابة (~5د)
6. (جلسة منفصلة) المرحلة 5: جدولة عبر CronCreate

ملاحظة: هذه الخطة لا تكسر ميزة قائمة، تحسّن نظامًا يعمل، تتجنب تكرار الكود، وتبقي الـ disclaimer + SEO + تصميم RTL كما هو. الجدولة الزمنية تتركز في جلسة منفصلة لتفادي تعارض الجداول في ZCode.
